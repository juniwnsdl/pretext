# 공개 문서 기반 전처리 개선 설계

- 작성일: 2026-07-31
- 상태: 사용자 방향 승인, 구현 계획 작성 전

## 목표

발전소 임직원이 보유한 법령·사규, Excel, 설명서·업무 매뉴얼, 일반 문서·보고서를 MISO RAG에 넣기 전에 구조를 보존해 `@@@` 청크로 전처리한다. 임베딩이나 의미 검색 모델을 추가하지 않고, 한 청크만 읽어도 문맥을 이해할 수 있으며 이어지는 내용과 원문 데이터가 조용히 누락·중복되지 않도록 한다.

## 확정 범위

1. Excel 병합·다단 머리행을 특정 파일명이나 제목에 의존하지 않고 병합 범위와 사용자가 선택한 머리행 범위로 합성한다.
2. 병합된 상위 제목과 하위 제목은 ` > `로 연결하고 연속 중복 제목은 제거한다.
3. 셀 줄바꿈과 현재 미리보기에 노출되는 `<br>` 표시는 열 제목에서 읽기 쉬운 공백으로 정규화한다.
4. 복잡한 병합·다단 머리행을 감지하면 사용자가 승인한 정확한 경고 문구를 결과에 표시하고 상태를 `원문 확인 필요`로 만든다.
5. Excel 사용자 설정에는 기존 머리행 범위 외에 `수식 출력 여부`만 추가한다. 다른 범위·열 이름·숨김 데이터 설정은 이번 구현 범위에서 제외한다.
6. 수식의 기본 출력은 파일에 저장된 계산 결과이며, 사용자가 선택하면 계산 결과와 수식 원문을 함께 출력한다.
7. 브라우저는 Excel 수식을 재계산하지 않는다. 저장된 계산 결과가 없는 수식은 경고하고, 결과 누락을 조용히 정상 처리하지 않는다.
8. 도움말의 `어떤 방법으로 문서를 처리하면 되나요?` 영역에 Excel 병합·다단 머리행, Excel 수식, Word/DOCX 표, HWP 변환 문서와 PDF 추출 표의 공통 확인 원칙을 추가한다.
9. 공개 정부·공공기관·공개 라이선스 문서를 우선 수집해 네 문서 유형(`law`, `excel`, `manual`, `general`)을 평가한다. 제3자 문서 원본 전체를 저장소에 재배포하지 않고, 필요한 경우 출처와 구조를 기록한 최소 회귀 fixture만 저장한다.
10. 기존 192개 회귀 테스트와 현재 정상 동작을 유지하며, 변경은 반드시 실패하는 테스트를 먼저 추가한 뒤 구현한다.

## Excel 병합 머리행 처리

### 입력 근거

- `DocumentBlock.rows`: 표시 문자열 행렬
- `DocumentBlock.merges`: 병합 범위와 시작·끝 좌표
- `excelLayout.usedRange`: 원본 시트의 사용 행 범위
- `excelLayout.headerRows`: 자동·저장·사용자 지정 머리행 범위

오프셋 시트에서도 병합·수식 좌표를 행렬에 정확히 대응시키기 위해 `excelLayout.usedRange`에 1부터 시작하는 `startColumn`, `endColumn`을 추가한다. 기존 요청·fixture에 이 값이 없으면 `startColumn=1`, 행렬의 최대 폭을 `endColumn`으로 간주해 호환한다.

수식은 다음 희소 메타데이터로 보존한다.

```ts
interface ExcelFormulaCell {
  row: number; // 1-based absolute Excel row
  column: number; // 1-based absolute Excel column
  formula: string; // leading = is normalized by the renderer
  hasStoredResult: boolean;
}
```

`DocumentBlock.formulaCells?: ExcelFormulaCell[]`로 전달하고 입력 검증에서는 표 셀 수 예산 안에서 좌표·문자열·개수를 검증한다. Workbook 전체 출력 선택은 `ExtractedDocument.excelOptions.formulaOutput`의 `'value-only' | 'value-and-formula'`로 보존한다.

### 합성 규칙

1. 선택한 머리행 범위 내부의 각 열을 독립적으로 처리한다.
2. 병합 셀의 좌상단 값을 그 병합 범위가 덮는 머리행 열의 문맥으로만 전파한다. 원본 데이터 행렬의 빈 셀을 실제 값으로 채우지는 않는다.
3. 각 열에서 위에서 아래로 발견한 제목 조각을 정규화하고 ` > `로 연결한다.
4. 줄바꿈, `<br>`, 연속 공백은 단일 공백으로 바꾼다.
5. 같은 제목이 연속되면 한 번만 남긴다.
6. 머리행 한 줄이고 병합이 없으면 기존 열 제목과 동일해야 한다.
7. 합성된 제목이 없는 열은 원문 값을 추측하지 않는다. 기존 빈 제목을 유지하되 `EMPTY_EXCEL_HEADER` 경고로 사용자가 원문을 확인하게 한다.
8. 머리행 병합이 데이터 행까지 걸치거나 머리행 범위를 벗어나면 자동 전파하지 않고 `COMPLEX_EXCEL_HEADER` 경고를 남긴다.

예시:

```text
대상 발전기 > Generation [MW]
대상 발전기 > Fuel Offtake [GJ]
대상 발전기 > Available Capacity [MW]
```

### 경고 문구

```text
복잡한 병합·다단 머리행이 감지되었습니다. 일부 열 이름이 데이터와 정확히 연결되지 않을 수 있습니다. 원본과 결과를 비교하거나 ‘엑셀 머리행 설정’에서 머리행 범위를 확인하세요.
```

## Excel 수식 처리

### 사용자 설정

- `계산 결과만 표시`(기본값)
- `계산 결과와 수식 함께 표시`

설정은 Workbook 전체에 적용하며 기존 머리행 설정 대화상자 안에 배치한다. 시트별 수식 설정은 이번 범위에 포함하지 않는다.

### 출력 규칙

- 저장된 계산 결과가 있으면 현재 표시 형식을 유지한다.
- 수식 포함을 선택하면 `표시값 (수식: =SUM(...))` 형태로 셀 값을 만든다.
- 수식은 있지만 저장된 결과가 없으면 `FORMULA_RESULT_MISSING` 경고를 생성하고 상태를 `원문 확인 필요`로 만든다.
- 저장 결과가 없고 `계산 결과만 표시`이면 셀은 기존 빈 표시값을 유지한다. `계산 결과와 수식 함께 표시`이면 `(수식: =SUM(...))`처럼 수식만 보존한다.
- 브라우저가 수식을 다시 계산하지 않는다는 점을 도움말과 결과 경고에서 설명한다.

수식이 존재하지만 저장 결과가 정상적으로 있는 경우에는 모든 결과를 경고 상태로 만들지 않는다. 설정 대화상자의 설명과 도움말로 재계산하지 않는다는 사실을 안내한다.

## 도움말 문구

`어떤 방법으로 문서를 처리하면 되나요?` 아래에 다음 내용을 추가한다.

> **표가 있는 문서는 이렇게 처리합니다**
>
> Excel은 시트와 표 영역을 구분하고 각 표의 머리행을 청크마다 반복합니다. 머리행이 여러 줄이거나 셀이 병합되어 있으면 병합된 상위 제목을 하위 열에 적용하고, `대상 발전기 > Generation [MW]`처럼 상위·하위 제목을 `>`로 연결하며 중복 제목은 제거합니다. 자동 감지 결과가 실제 표와 다르면 `엑셀 머리행 설정`에서 머리행 범위를 확인하세요.
>
> 수식이 포함된 Excel은 파일에 저장된 마지막 계산 결과를 사용합니다. 이 전처리기는 Excel 수식을 다시 계산하지 않으므로 최신 값이 필요한 경우 Excel에서 수식을 다시 계산한 뒤 저장하고 업로드하세요. 설정에서 계산 결과만 표시하거나 계산 결과와 수식을 함께 표시할 수 있습니다.
>
> Word/DOCX, HWP를 DOCX·PDF로 변환한 문서, PDF 추출 결과의 표도 같은 원칙으로 확인해야 합니다. 병합 셀, 여러 줄 머리행, 표 안의 다른 표, 페이지를 넘어가는 표는 열 제목이나 셀 관계가 달라질 수 있으므로 결과 표의 머리행과 행·열 관계를 원문과 비교하세요. HWP는 직접 지원하지 않으며 DOCX 또는 PDF로 변환한 뒤 처리합니다.

## 공개 문서 평가

### 출처 원칙

- 정부·공공기관 원문, 국가법령정보센터, 공공데이터포털, 공공기관 공개 자료를 우선한다.
- 커뮤니티 자료는 재배포가 허용되거나 구조 확인에 필요한 최소 인용만 가능한 경우에 한해 평가 참고로 사용한다.
- 원문 URL, 접근일, 문서 유형, 파일 형식, 사용한 구조 특성을 평가 기록에 남긴다.
- 다운로드한 원본은 임시 평가 자료로 두고 저장소에는 최소 fixture 또는 구조화된 기대값만 커밋한다.

### 문서 유형별 평가 초점

- 법령·사규: 편·장·절·관·조, 부칙, 별표·별지, 같은 줄 조문, 긴 조문
- Excel: 단일·다중 시트, 병합·다단 머리행, 수식, 여러 표, 긴 셀
- 설명서·업무 매뉴얼: 번호 단계, 주의·경고, Heading 없는 DOCX, 긴 단계, 표
- 일반 문서·보고서: 제목 계층, 목록, 인용, 표 전후 산문, 계약서형 조문

각 유형은 요구 일치, 구조 변형, 원문 보존, 3,800/4,000자·`@@@`, 테스트 사각지대의 다섯 관점으로 다시 평가한다.

## 회귀 방지

- 기존 테스트 전체를 변경 전후에 실행한다.
- 각 수정은 실제 실패 사례를 재현하는 테스트를 먼저 추가하고 실패를 확인한다.
- 단순 한 줄 머리행 Excel과 병합이 없는 표의 기존 출력은 변경하지 않는다.
- Excel 수식 설정의 기본값은 기존 표시값 출력과 호환되어야 한다.
- 기존 구조화 요청에 사용 열 범위·수식 메타데이터가 없어도 기존 동작이 유지되어야 한다.
- 도움말 변경은 기존 탭 순서와 문서 유형 선택 안내를 유지한다.
- 실제 공개 문서에서 발견한 문제는 최소 재현 fixture와 명확한 기대 결과로 축소한다.

- HWP 직접 파서
