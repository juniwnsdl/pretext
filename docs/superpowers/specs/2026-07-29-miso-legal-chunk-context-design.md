# MISO 법령형 문서 청크 문맥 보존 설계

## 배경

MISO가 추출한 법령·계약·사규 문서는 조문 제목과 본문이 같은 줄에 들어올 수 있다.

```text
제10조(기타) 기본품의에 관한 사항을 정한다.
```

기존 구현은 한 줄 전체 길이가 120자 이하일 때만 구조 제목으로 취급했다. 이 때문에 짧은 `제9조`는 제목으로 인식하지만, 본문까지 포함되어 120자를 넘은 `제10조`는 새 조문으로 인식하지 못했다. 이후 전체 내용이 제9조 본문으로 묶이고, 4,000자 분할 과정에서 `제9조 ... (계속)`이 여러 청크에 잘못 반복됐다.

DOCX의 페이지 머리글·바닥글도 MISO 출력 본문에 평탄화된다. 제공된 계약조건 문서에서는 `제2편 계약조건`, 사업명, 권명이 페이지마다 반복되며, `제2편`이 실제 구조 제목으로 오인되어 조문 경계를 방해한다.

## 목표

- 한 줄에 조문 제목과 본문이 함께 있어도 두 부분을 정확히 분리한다.
- 4,000자를 넘는 실제 조문만 분할하고, 각 분할 청크에 해당 조문 제목을 반복한다.
- 조문 제목 반복 시 `(계속)`을 붙이지 않는다.
- 앞 조문의 제목이 뒤 조문 내용에 반복되지 않도록 한다.
- 반복되는 짧은 페이지 머리글·바닥글을 특정 문구 하드코딩 없이 감지한다.
- 페이지 번호와 의미 있는 반복 본문은 보존한다.
- 법령·사규와 일반 문서에서 같은 법령형 입력은 일관되게 처리한다.

## 비목표

- MISO의 임베딩, 벡터 저장 또는 검색 동작은 변경하지 않는다.
- 문서의 모든 중복 문장이나 문단을 제거하지 않는다.
- OCR 오탈자 전체를 교정하지 않는다.
- 엑셀 행·헤더 청킹 규칙은 변경하지 않는다.
- 특정 계약서의 머리글 문구를 코드에 직접 등록하지 않는다.

## 설계 결정

### 1. 반복 페이지 장식 감지

공통 텍스트 정규화 이후, 구조 분석 전에 반복 페이지 장식을 제거한다. 이 단계는 법령·사규, 설명서·업무 매뉴얼, 일반 문서에 적용하고 엑셀에는 적용하지 않는다.

페이지 번호는 다음과 같은 형태를 포함하여 감지하되 절대 제거하지 않는다.

```text
2-26
페이지 3
Page 3
3 / 56
```

반복 페이지 장식 후보는 다음 조건을 모두 만족하는 줄이다.

- 앞뒤 공백을 제외한 길이가 2~80자다.
- 동일하게 정규화된 줄이 문서에서 3회 이상 등장한다.
- 반복 위치 사이에 최소 8개의 비어 있지 않은 줄이 있어, 한 위치의 단순 연속 중복이 아니다.
- 표 행, 목록 항목, 문장형 본문이 아니다.
- 페이지 번호 앞뒤 3개의 비어 있지 않은 줄 안에서 반복되거나, 2줄 이상의 동일한 짧은 문구 묶음이 문서의 서로 떨어진 위치에서 3회 이상 반복된다.

감지된 페이지 장식은 첫 번째 등장만 원래 위치에 보존하고 이후 반복을 제거한다. 이를 통해 문서명·사업명·권·편 정보는 한 번 남기면서 조문 청킹을 방해하는 반복만 없앤다.

페이지 번호는 후보 판단을 위한 기준으로만 사용하고 결과 텍스트에는 모두 남긴다. `동일 안내`, `주의`, 면책문 등 일반 반복 내용은 위 조건을 충족하지 않으면 제거하지 않는다. 판단이 불확실하면 보존하는 쪽으로 처리한다.

### 2. 법령 구조 줄 파싱

불리언 제목 판별 함수 대신 다음 정보를 반환하는 파서를 사용한다.

```ts
type LegalStructureLine = {
  kind: 'part' | 'chapter' | 'section' | 'subsection' | 'article' | 'addendum' | 'appendix' | 'form';
  heading: string;
  inlineBody: string;
  leadingMetadata: string;
};
```

파서는 줄 전체 길이를 제한하지 않는다. 다음 형태를 인식한다.

```text
제10조(기타) 본문...
제10조 (기타) 본문...
제3조의2(환경위성 관측망의 구축·운영 등) 본문...
제2편 계약조건
제1장 총칙
부칙
별표 1
1.136. [1.1.137.] 제40조 (지체 및 지체상금) 본문...
```

조문은 `제N조` 또는 `제N조의M`과 선택적인 괄호 제목까지만 `heading`으로 분리한다. 그 뒤의 문장은 길이와 관계없이 `inlineBody`에 넣는다. 괄호 제목이 없는 경우에는 `제N조` 또는 `제N조의M`까지만 제목으로 사용해 본문을 제목으로 오인하지 않는다.

MISO가 앞에 붙인 숫자·대괄호 번호는 `leadingMetadata`로 분리한다. 이 값은 원문 보존을 위해 첫 번째 청크에 한 번만 남기고, 분할 청크에 반복할 조문 제목에는 포함하지 않는다.

### 3. 구조 블록 생성

파싱된 구조 줄이 나오면 이전 블록을 닫고 새 블록을 시작한다. 같은 줄의 `inlineBody`는 새 블록의 첫 본문으로 넣는다. 따라서 제10조가 긴 한 줄이어도 제9조의 본문으로 들어가지 않는다.

법령·사규는 법령 구조 파서를 기본으로 사용한다. 일반 문서는 법령 구조가 하나라도 발견되면 같은 구조 파서를 사용하고, 발견되지 않으면 기존 문단·표 청킹을 유지한다.

설명서·업무 매뉴얼의 기존 제목 구조는 유지하되, 장문 구간의 후속 청크에서도 `(계속)` 대신 해당 매뉴얼 제목을 그대로 반복한다. 위임전결 전용 카테고리도 `[위임전결규정 매뉴얼]\nA. 일반 공통` 같은 기존 문맥 접두사를 그대로 반복하고 `(계속)`은 붙이지 않는다.

### 4. 4,000자 초과 조문 분할

구조 블록 전체가 4,000자 이하면 조문을 분할하지 않는다. 여러 개의 작은 조문은 4,000자 이내에서 하나의 청크로 병합할 수 있지만, 각 조문의 제목과 본문은 함께 이동한다.

구조 블록이 4,000자를 넘으면 다음 순서로 처리한다.

1. 이전 병합 버퍼를 먼저 확정한다.
2. 반복할 `heading`과 줄바꿈 길이를 4,000자에서 제외해 본문 가용 크기를 계산한다.
3. 본문만 문단·줄·문장·표 경계를 우선해 분할한다.
4. 모든 결과 청크 상단에 동일한 `heading`을 붙인다.
5. `leadingMetadata`는 첫 번째 결과 청크에만 붙인다.
6. `(계속)` 문자열은 추가하지 않는다.

예시는 다음과 같다.

```text
제2조(정의)
본문 1...

@@@

제2조(정의)
본문 2...
```

제9조와 제10조가 각각 4,000자 이하라면 두 제목은 원문에 있는 한 번씩만 출력된다. 제2조만 4,000자를 넘는다면 제2조만 자신의 분할 청크 수만큼 반복된다.

### 5. 페이지 번호 보존

기존 위임전결 전용 처리에서 `페이지 N` 줄을 제거하는 필터를 없앤다. 페이지 번호는 반복 머리글 탐지에 활용할 수 있지만, 모든 문서 유형에서 출력 내용으로 보존한다.

### 6. 실패 시 동작

- 구조 줄을 확실하게 파싱하지 못하면 일반 문단·표 청킹으로 되돌아간다.
- 반복 페이지 장식 판단이 불확실하면 해당 줄을 보존한다.
- 하나의 제목 자체가 4,000자에 가까운 비정상 입력은 제목 식별자만 문맥 접두사로 사용하고 나머지는 본문으로 처리한다.
- 본문 문자는 자동 오버랩으로 복제하지 않는다. 의도적으로 반복되는 것은 구조 제목뿐이다.

## 처리 흐름

```text
MISO 추출 텍스트
  → 공백·제어문자 정규화
  → 반복 페이지 장식 감지 및 이후 반복 제거
     (페이지 번호는 유지)
  → 문서 유형별 구조 분석
  → 조문 제목 / 같은 줄 본문 분리
  → 구조 블록 생성
  → 4,000자 이하 블록 병합 또는 장문 블록 본문 분할
  → 필요한 청크에만 정확한 조문 제목 반복
  → @@@ 삽입
```

## 테스트 전략

다음 동작을 실제 전처리 공개 함수로 검증한다.

1. 204자가 넘는 `제10조(기타) 본문...`도 제9조와 별도 조문으로 분리된다.
2. 제2조만 4,000자를 넘으면 제2조 제목만 해당 분할 청크에 반복된다.
3. 제9조와 제10조가 4,000자 이하라면 각 제목은 한 번만 출력된다.
4. 분할된 모든 제2조 청크가 `(계속)` 없이 `제2조(정의)`로 시작한다.
5. `제3조의2`와 공백이 있는 `제40조 (제목)`을 인식한다.
6. MISO 숫자·대괄호 접두사는 첫 청크에만 보존되고 조문 제목에는 섞이지 않는다.
7. 반복 머리글 세 줄은 첫 묶음만 남고 이후 반복은 제거된다.
8. `2-26`, `페이지 3`, `Page 3` 같은 페이지 번호는 모두 보존된다.
9. 반복되는 업무 문단과 의미 있는 구두점은 기존처럼 보존된다.
10. 마크다운 표가 포함된 장문 조문은 표 헤더와 행 경계를 보존한다.
11. 법령·사규와 일반 문서가 동일한 법령형 입력에서 같은 조문 경계를 만든다.
12. 기존 위임전결 매뉴얼의 A~J 카테고리 분리와 표 문맥이 유지된다.

## 성공 기준

- 제공된 계약조건 문서에서 페이지 번호는 유지되고 반복되는 문서 머리글 3종은 각각 한 번만 남는다.
- 제4조의 도입문과 계약문서 목록이 같은 구조 블록에 남는다.
- 장문 조문 후속 청크는 자신의 조문 제목으로 시작하며 앞 조문 제목이나 `(계속)`을 포함하지 않는다.
- 현재 전처리 테스트와 새 회귀 테스트가 모두 통과한다.
- TypeScript 타입 검사와 Next.js 프로덕션 빌드가 성공한다.
