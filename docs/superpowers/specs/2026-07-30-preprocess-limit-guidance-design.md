# 전처리 입력 제한 상향 및 안내 설계

## 목표

전처리 입력 안전 제한을 실사용 범위에 맞게 완화하고, 엑셀 사용자가 처리 전에 제한을 확인하며 제한 초과 시 파일 분할 방법을 알 수 있게 한다.

## 제한값

- 시트당 최대 행 수: 5,000행에서 20,000행으로 상향
- 시트당 최대 셀 수: 100,000셀에서 300,000셀로 상향
- 문서 전체 구조 항목 수: 1,000,000개에서 2,000,000개로 상향
- 최대 열 수 512개, 최대 텍스트 길이 50,000,000자 등 나머지 제한은 유지

제한값은 브라우저 화면과 서버 검증에서 함께 사용할 수 있는 공통 모듈 한 곳에 선언한다. 기존에 `lib/preprocess-request.ts`에서 제한 상수를 가져오는 코드는 깨지지 않도록 같은 이름으로 다시 내보낸다.

## 사용자 안내

### 파일 선택

엑셀 파일을 선택했을 때 기존 처리 방식 안내 카드 아래에 다음 내용을 작은 빨간 글씨로 표시한다.

> 시트당 20,000행·300,000셀을 초과하면 파일을 나눠 처리해 주세요.

다른 파일 형식을 선택했을 때는 이 문구를 표시하지 않는다.

### 제한 초과 오류

기존 영문 오류 대신 다음과 같이 한국어로 원인과 조치를 안내한다.

> 문서가 전처리 입력 제한을 초과했습니다. 엑셀은 시트당 20,000행·300,000셀 이하로 나누고, 다른 문서는 파일을 여러 개로 분리해 다시 시도해 주세요.

레거시 텍스트 입력의 제한 초과 오류도 한국어로 바꾸되 기존 오류 코드 `INPUT_TOO_LARGE`는 유지한다.

### 도움말

도움말의 `파일 업로드` 섹션에 엑셀의 시트당 행·셀 제한과 초과 시 파일 분할 권장을 추가한다. 기존 50MB 파일 용량 안내와 함께 보여주되, 행·셀 제한이 파일 용량과 별개의 기준임을 짧게 표현한다.

## 구현 경계

- 제한 초과 원인을 행·셀·전체 구조별로 세분화하는 기능은 이번 범위에 포함하지 않는다.
- 대용량 엑셀 자동 분할 기능은 포함하지 않는다.
- 기존 파일 처리 방식과 전처리 결과 생성 로직은 변경하지 않는다.

## 테스트

- 공통 제한 상수가 새 값인지 검증한다.
- 새 경계값까지 허용하고 경계값을 넘으면 기존처럼 `INPUT_TOO_LARGE`가 반환되는지 검증한다.
- 엑셀 처리 안내와 도움말 레이아웃에 행·셀 제한 문구가 포함되는지 검증한다.
- 전체 테스트와 TypeScript 검사를 실행한다.
