# 청크 경계 드래그 정확성 개선 설계

## 목적

4단계 결과 검토 화면의 현재 디자인과 조작법을 유지하면서, 드래그 미리보기와 실제 청크 변경이 항상 동일한 자연어·Markdown 경계에 적용되도록 한다.

## 범위

- 청크 색상, 세로 배치, 경계 손잡이, 빨간 미리보기 선, 하단 미리보기 카드의 외형을 유지한다.
- 사용자는 지금처럼 청크 사이 손잡이를 위아래로 드래그하고 마우스를 놓아 변경을 적용한다.
- 마우스 위치를 렌더링된 Markdown의 임의 문자 오프셋으로 변환하는 기존 방식은 제거한다.
- 문서 전처리 알고리즘과 4,000자 청크 생성 규칙은 변경하지 않는다.

## 검토한 접근

1. **구조 기반 경계 모델 — 선택**
   원문에서 유효한 경계를 계산하고, 렌더링된 블록 위치와 연결한다. 미리보기와 적용이 하나의 경계 객체를 공유하므로 정확성과 예측 가능성이 가장 높다.
2. **기존 caret 위치 계산 보정 — 제외**
   변경량은 작지만 강조, 링크, 인라인 코드, 중첩 목록 등 Markdown DOM 구조마다 별도 보정이 필요해 계속 취약하다.
3. **블록 이동 버튼 UI — 제외**
   정확하지만 현재 드래그 디자인과 조작 경험을 바꾸므로 사용자 요구와 맞지 않는다.

## 경계 모델

각 청크 원문에서 다음 순서로 유효 경계를 만든다.

1. 빈 줄로 구분된 Markdown 블록 경계
2. 제목과 뒤따르는 본문을 분리하지 않는 섹션 경계
3. 목록·표·코드 블록의 바깥 경계
4. 단일 긴 일반 문단에서는 한국어를 지원하는 문장 종결 경계

청크의 시작과 끝은 이동 후보에서 제외하여 빈 청크가 남지 않게 한다. 제목 바로 뒤의 본문 시작점도 후보에서 제외하여 제목만 이전 청크에 고립되지 않게 한다.

## 렌더링과 데이터 흐름

유효 경계는 다음 정보를 가진다.

- 대상 청크 인덱스
- 원문 기준 분할 `offset`
- 렌더링된 경계를 식별하는 안정적인 ID
- 미리보기 전후 문맥

드래그 중에는 포인터 Y 좌표와 가장 가까운 렌더링 경계를 선택한다. 선택된 경계의 실제 DOM Y 좌표에 빨간 선을 표시하고, 미리보기 카드도 같은 `offset`에서 내용을 만든다. 마우스를 놓으면 별도 재계산 없이 현재 선택된 경계의 `offset`을 그대로 적용한다.

```text
포인터 위치
  -> 가장 가까운 유효 경계
     -> 빨간 선 위치
     -> 미리보기 문맥
     -> 실제 청크 변경 offset
```

## 상호작용

- 손잡이와 마우스 커서 디자인은 유지한다.
- 빨간 선은 포인터를 픽셀 단위로 추적하지 않고 가장 가까운 유효 경계에 스냅된다.
- `Esc` 취소 동작을 유지한다.
- 인접한 두 청크 밖으로 포인터가 나가면 마지막 유효 경계를 유지하되 적용 대상은 확장하지 않는다.
- 드래그 이벤트 리스너는 드래그 시작과 종료 때만 연결하고, 최신 선택 경계는 ref로 보관하여 마우스 이동마다 리스너를 재등록하지 않는다.

## 오류 및 예외 처리

- 유효 경계를 찾지 못하면 미리보기를 표시하거나 청크를 변경하지 않는다.
- 적용 결과 어느 한 청크가 빈 문자열이 되면 변경하지 않는다.
- Markdown 제목, 목록, 표, 코드 블록 내부의 구조를 깨는 경계는 후보로 만들지 않는다.

## 검증

- 미리보기에서 선택한 `offset`과 실제 적용 함수에 전달된 `offset`이 동일하다.
- 강조·링크·인라인 코드가 포함된 문단에서도 가리킨 섹션 근처 경계를 선택한다.
- 제목을 가리켜 드래그해도 제목과 바로 뒤 본문이 서로 다른 청크로 분리되지 않는다.
- 긴 일반 문단은 가까운 문장 종결 위치에 스냅된다.
- 청크 시작·끝으로 드래그해도 빈 청크가 생성되지 않는다.
- 기존 색상, 손잡이, 빨간 선, 미리보기 카드가 유지된다.
- 전체 테스트, TypeScript 검사, 프로덕션 빌드를 통과한다.
